# I18N.md — translatable text

The app authors every string in English and translates by looking that English
up. There is no key id layer, so nothing renames when a wording is corrected.

## The rules

1. **A key is its English source text.** `t("Save")`, never `t("action.save")`.
   Correcting a wording mints a new key; the catalogue regeneration retires the
   old one.
2. **Every user-visible string goes through `t()`.** A literal that reaches the
   DOM untranslated is a defect, including one built by a helper or held in a
   label map.
3. **A translation catalogue is generated, never hand-keyed.** The extractor
   owns the key set; a contributor edits values only. An empty value means
   untranslated and renders the English source — never blank.
4. **A locale is a `Locale` union member plus its catalogue.** Nothing else
   branches on locale, and no engine path, storage key or test may.
5. **Interpolate outside `t()`.** A key built by interpolation is translatable
   only where the collector enumerates every string it can produce; unless it
   does, pass fixed text and compose the number around the call.
6. Chinese stays out of `src/` and `tests/` — CLAUDE.md § "Language".

Renaming a locale's own union member is a storage change and needs a migration;
adding one is not, because an unknown stored value already falls back.

## Where a string comes from

The extractor reads two sources and neither is authoritative over the other:

- **UI text** — string literals reaching `t()` in `src/`, directly or through a
  module-level label map or a helper's `return`.
- **Content text** — display fields on the registries, read by importing them.

A string reachable through neither is invisible to the catalogue. That is the
one failure the drift test cannot report, so a new label map goes at module
scope and a new display field goes on a registry the collector already reads.
